\chapter{Gold and Judge Protocols}\label{app:gold-and-judge-protocols}

\section*{Writing the gold}
\begin{enumerate}[nosep]
\item The gold is written by Claude from the source files only, before any output of the system for those files is
opened; the writer records which files it read.
\item Every item carries verbatim evidence: a sentence of its chunk, a record of its table, or a SQL query whose
answer equals the gold answer. A test checks all three on every committed gold file.
\item Each benchmark and confirmation file is reviewed twice by independent reviewers, who re-derive every answer from
the sources, re-run every query and look for repeats of facts asked before; a third pass applies or answers every
finding.
\item A gold item changed after outputs were seen is a \emph{gold correction}, listed with its reason in the step that
made it.
\end{enumerate}

\section*{Judging answers by meaning}
The judge decides each answer against the gold answer and its evidence by six fixed rules (the examples in the rules
are invented):
\begin{enumerate}[nosep]
\item \emph{Correct by meaning}: an answer is correct when it states what the expected answer states, in any wording;
extra detail is fine when it is true of the source and contradicts nothing.
\item \emph{Every part}: when the expected answer has several parts, an answer missing one part is wrong.
\item \emph{Content, not form}: what the answer says is judged in whichever field it gives it.
\item \emph{A partial value is wrong}: only the year of an expected date, or a generic phrase for a specific one, does
not answer the question.
\item \emph{No answer is wrong}: ``the texts do not say'' is wrong when the expected answer exists in the source.
\item Judge against the expected answer and its evidence only, never against outside knowledge.
\end{enumerate}
Two judges work blind and independently on each answers file; a lead judge decides their disagreements. Verdicts are
written to a file with a one-line reason per verdict, and code computes the scores from it.

\section*{Judging builder outputs}
Each item (a stored claim, a merge, a mention-to-record link, a pair of a start and a chunk) receives one of five
labels: \emph{valid}, \emph{valid alternative}, \emph{incorrect}, \emph{ambiguous}, \emph{unjudgeable}. One blind judge
labels each batch; the lead reviews every label other than valid and a seeded random 10\,\% of the valid ones. Rates
are computed by code as defined in \cref{sec:ch03-scoring-exact-match-and-judgement}.

\chapter{Reproducibility Guide}\label{app:reproducibility-guide}

\section*{Environment}
The code, records and figures are in the project repository; the thesis is built from the branch \texttt{thesis}.
Python dependencies are installed with \texttt{uv sync}; Neo4j~5 with APOC (and an optional PostgreSQL) run from the
repository's Docker Compose file. Model calls need a Gemini API key; every response is cached under
\texttt{.cache/llm}, so a repeated command costs nothing.

\section*{Building a graph}
\begin{lstlisting}
uv run kg --preset quality run --goal "supply chain root cause analysis"   # furniture
uv run kg --preset heldout run --goal "..."     # NHTSA; generality_gemini, ntsb likewise
\end{lstlisting}
Each stage can be run alone (\texttt{profile}, \texttt{plan}, \texttt{build}, \texttt{ingest-text},
\texttt{text-schema}, \texttt{extract}, \texttt{link}, \texttt{mention-pass}, \texttt{resolve}, \texttt{attach},
\texttt{index}); the recipe each final build used is recorded in \path{tests/gold/<step>/runs.json}. Reloading a
graph from the cache reproduces it exactly, which its digest confirms.

\section*{Answering and scoring}
\begin{lstlisting}
uv run kg --preset quality qa tests/gold/qa/furniture_qa_bench.json --system agent --out out/run
uv run kg qa-score ...    # exact match, or by meaning with a verdicts file
uv run kg qa-compare ...  # paired McNemar between two outcome files
uv run kg serve           # the web interface
\end{lstlisting}

\section*{Figures and the thesis}
\begin{lstlisting}
uv run python -m figures.scripts.build          # every figure from committed records
uv run python thesis/tools/export_appendix.py   # Appendices A, D, F
cd thesis && latexmk -xelatex main.tex          # or Tectonic with biber 2.17
\end{lstlisting}

\section*{Cost}
At list prices, a build costs \$0.37--1.42, a question about \$0.016 at low thinking, and the whole sequence of
unseen-question runs on the four datasets \$7.22. Judging was done in a Claude session at no API cost. Embedding calls
are not priced.
